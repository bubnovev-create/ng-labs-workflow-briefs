# Permission acceptance review

Pair an allowed journey with a refused journey before a demonstration. Identify the account role, resource/version, starting state, expected result and actual result. Use a separate record for each meaningful combination.

For example, agree what happens when another customer follows a copied record link, a reviewer attempts an approval, or a person returns after access changes. These are illustrative requirements, not a report of a client system or a security certification.
