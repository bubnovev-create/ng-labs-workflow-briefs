# NG Labs — Workflow Briefs

Practical planning templates for a web application or client portal. Start with one task, the people allowed to act, and the evidence that shows completion.

NG Labs is a brand of **North Growth Lab LLC**. This is an original reference collection, not a client system, framework, monitoring service or security certification. No customer records, credentials or production code are included.

## Use the collection

1. Complete [the workflow scope](workflow-scope.md) for one useful journey.
2. Fill [the role and access matrix](role-access-matrix.md), including actions that must be refused.
3. Write [the integration recovery decisions](integration-recovery.md) for an unresolved exchange.
4. Use [the permission acceptance review](permission-review.md) to pair allowed and refused journeys.
5. Review [the handover checklist](handover-checklist.md) with the people who will operate the product.

Replace illustrative examples with agreed requirements. Leave credentials and private customer records out of these files. A completed template is a discussion artifact; it does not prove that the controls are implemented or that an integration is available.

## Worked example

An illustrative service request moves from a customer to a reviewer and then an approver. The application sends an approved request to an operational tool. If no confirmation is available, the request stays visibly unresolved. An authorised operator checks the identified version and destination outcome before deciding whether to repeat the exchange. A late confirmation is reconciled against the same reference. This example describes no live customer system.
